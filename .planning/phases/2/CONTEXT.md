A section the dump touches but leaves thin gets a guess tagged `[ASSUMPTION]`. No section is ever left empty. Evidence: `.planning/ROADMAP.md` phase 2 criteria 2 and 3; `.planning/REQUIREMENTS.md` FLOW-07; `docs/FORMAT.md` (no section is empty); `skills/seldon/SKILL.md`.
- D-02 (permissions, SECURITY): SKILL.md `allowed-tools` adds Read, Glob and Grep, plus exactly two rules that can change anything: `Edit(.planning/seldon/**)` and `Bash(node ${CLAUDE_PLUGIN_ROOT}/lib/check.mjs:*)`. A `Write(path)` rule is accepted but never matches, and `Edit` rules apply to every built-in tool that edits files, so `Edit(.planning/seldon/**)` is the only path-scoped write rule there is and it's narrower than plain Write. `Bash(node:*)` is ruled out, because `node -e` runs anything. Evidence: `/tmp/claude-1000/-code-seldon/d6bc5d0d-ef34-4d16-bbdd-f325a2be7df0/scratchpad/docs/permissions.md:344,359-363` (Edit rules cover all file-editing tools; Write(path) rules don't match); `skills.md:497-500` (`${CLAUDE_PLUGIN_ROOT}` is substituted in a plugin skill's text and in its allowed-tools Bash rules); ruling relayed by mother under John's overnight go, which corrected an earlier "No Edit" to mean no unscoped write power.

## Decisions

- D-08 (existing brief): Until phase 3 adds rerun, `/seldon` stops without writing when `.planning/seldon/brief.md` already exists, and says that rerunning a step comes later. Evidence: `.planning/ROADMAP.md` phase 3 (FLOW-02, FLOW-03).
- D-09 (fast-path questions): On the fast path, all the questions that block the brief go in one prose turn. Coaching keeps one question per turn. Evidence: `skills/seldon/SKILL.md`; phase 1 D-06.
- D-10 (coaching): Phase 2 builds the coaching path through to a written brief, and one more replay case, whose history finishes the coaching answers, checks that the brief gets written. Evidence: `.planning/ROADMAP.md` phase 2 goal; `references/test-policy.md` (a behavior change needs adequate automated coverage).
- D-11 (design folder): Seldon reads `docs/design/` when it exists, plus any folder the dump points to, as read-only input to the brief. Evidence: `.planning/REQUIREMENTS.md` DOCS-03; `docs/FORMAT.md`; `README.md`.
- D-12 (scaffold): The first scaffold scripts arrive in this phase, not phase 3, each with phase 1 D-07's Node guard test. The `docs/design/` fixture lives under `samples/`, and AC6's scaffold copies only `samples/brief.md` into the run directory's `.planning/seldon/`. Every scaffold copies fixture files from `samples/` and does nothing else. Evidence: `.planning/phases/1/CONTEXT.md` D-07; mother's ruling on AC6.
- D-13 (eval cases): The case proving "writes nothing until confirmed" allows Write and grades `tool_used` Write max 0, so a premature write is possible and caught. The new fast-path brief case's dump leaves at least one section unstated but inferable, so a tagged guess has to appear. Section completeness is graded through the check's result line, which Seldon repeats in its final message, and a regex on the brief file is also available. Evidence: `evals/fast-path/prompt.md` (allows only Skill and AskUserQuestion); `.planning/ROADMAP.md` phase 2 criteria 1 and 2.
- D-14 (phase 1 replay): Phase 1's replay case stays. When the user confirms coaching, Seldon still names the project before its first coaching question, so the `Brindlewick` grader keeps passing. Evidence: `evals/replay/prompt.md`; `evals/replay/graders/recalls-transcript-fact.md`.

Eval verification runs in the main tree, never from a worktree executor. The README's eval command gains `--scaffold`. Evidence: `evals/replay/history.jsonl`; `evals/.gitignore`; `.planning/phases/1/SUMMARY.md` deviations.
