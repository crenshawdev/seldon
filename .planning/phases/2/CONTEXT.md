## Scope boundary

In: The brief step of `/seldon`, built on phase 1's skeleton in `skills/seldon/SKILL.md`. It takes the user's dump, recommends fast path or coaching from the stakes, waits for the user to confirm, asks what the dump left open, and writes `.planning/seldon/brief.md`. It reads `docs/design/` (or a folder the dump names) as read-only input. A brief-only mode for `lib/check.mjs`, with `docs/FORMAT.md` and the tests updated to match. The `[ASSUMPTION]` tag documented in FORMAT.md. SKILL.md `allowed-tools` under D-02. The first scaffold scripts and their guard test, under phase 1's D-07. New eval cases proving AC1 to AC6, plus the README's eval command gaining `--scaffold`.
Out: The PRD, spine and epics steps (phases 3 to 5). Resume after `/clear` and `/seldon <step>` rerun (phase 3). The epic size and trace checks (phases 5 and 8). Any scaffold that does more than copy fixture files from `samples/`.
Deferred: None
Plan shape: multiple plans - several plans inside this phase; plans that share `skills/seldon/SKILL.md` run in order.

## Durable decisions

- D-01 (interview): On the fast path, Seldon asks before drafting only about a brief section the dump never mentions that only the user can decide, and "who it serves" is always in that group. A section the dump touches but leaves thin gets a guess tagged `[ASSUMPTION]`. No section is ever left empty. Evidence: `.planning/ROADMAP.md` phase 2 criteria 2 and 3; `.planning/REQUIREMENTS.md` FLOW-07; `docs/FORMAT.md` (no section is empty); `skills/seldon/SKILL.md`.
- D-02 (permissions, SECURITY): SKILL.md `allowed-tools` adds Read, Glob, Grep, Write, and Bash narrowed to the exact check command, prefix-matched (for example `Bash(node <plugin root>/lib/check.mjs:*)`, in whatever form the planner proves works). `Bash(node:*)` is ruled out, because `node -e` runs anything and so grants a shell. If no tight Bash form can be proven, Bash stays out of `allowed-tools` and the check runs behind a permission prompt. Write is scoped to `.planning/seldon/**` if the permission syntax supports a path, and the plan records whether it does. No Edit. Evidence: `skills/seldon/SKILL.md` frontmatter (phase 1 granted none of Write, Edit, Bash, AskUserQuestion); ruling relayed by mother under John's overnight go.
- D-03 (eval proof of the write boundary): No grader hashes files, so DOCS-03's case proves the read by a fact found only in the design fixture showing up in Seldon's reply. It proves the boundary with `tool_used` graders using `input_match`: Edit max 0, Write max 0 for any `file_path` outside `.planning/seldon/`, and Bash max 0 for anything but the check command. These back D-02 up whatever `allowed-tools` ends up holding. Evidence: https://code.claude.com/docs/en/plugin-evals.md (`tool_used` takes `input_match`, `min`, `max`; regex targets include `{ source: file, path }`; `file_exists` counts only files Claude created).
- D-04 (confirmation): Nothing is drafted until the user confirms a path in a later turn. Every case that produces a brief replays a `context.history_file` ending at the recommendation question, with the user's confirmation as the case prompt. Phase 1's single-turn fast-path case stays as the "recommends and writes nothing" check. Evidence: `skills/seldon/SKILL.md` (the skeleton ends the turn after the recommendation); `evals/fast-path/prompt.md`; `evals/replay/history.jsonl`; `.planning/REQUIREMENTS.md` FLOW-06.
- D-05 (check): `lib/check.mjs` gains a brief-only mode with its own result line, distinct from "all four documents conform". `docs/FORMAT.md`'s "The check" section and the Node tests change with it. The full check still requires all four files. Evidence: `lib/check.mjs` (`checkDir` reads all four files today; `main` reads only the first argument); `docs/FORMAT.md` "The check"; phase 1 D-05.
- D-06 (tag): The tag is spelled exactly `[ASSUMPTION]` and sits inline after the guessed text. `docs/FORMAT.md` documents it as part of the contract Cadence's reader gets, and `lib/check.mjs` doesn't enforce it. Evidence: `BRIEF.md` "How it runs"; `docs/FORMAT.md` (no mention today); `.planning/PROJECT.md` (`/cad-new-project` asks only about gaps).
- D-07 (check location): The skill runs the plugin's own installed `lib/check.mjs`, found from the plugin root, and never a path in the user's project, which has no `lib/check.mjs`. Evidence: `.github/workflows/test.yml` (the installed check runs from `installPath`); `lib/check.mjs` (the realpath guard for the installed-path case); `evals/results/` (the plugin path differs from the run's cwd).

## Decisions

- D-08 (existing brief): Until phase 3 adds rerun, `/seldon` stops without writing when `.planning/seldon/brief.md` already exists, and says that rerunning a step comes later. Evidence: `.planning/ROADMAP.md` phase 3 (FLOW-02, FLOW-03).
- D-09 (fast-path questions): On the fast path, all the questions that block the brief go in one prose turn. Coaching keeps one question per turn. Evidence: `skills/seldon/SKILL.md`; phase 1 D-06.
- D-10 (coaching): Phase 2 builds the coaching path through to a written brief, and one more replay case, whose history finishes the coaching answers, checks that the brief gets written. Evidence: `.planning/ROADMAP.md` phase 2 goal; `references/test-policy.md` (a behavior change needs adequate automated coverage).
- D-11 (design folder): Seldon reads `docs/design/` when it exists, plus any folder the dump points to, as read-only input to the brief. Evidence: `.planning/REQUIREMENTS.md` DOCS-03; `docs/FORMAT.md`; `README.md`.
- D-12 (scaffold): The first scaffold scripts arrive in this phase, not phase 3, each with phase 1 D-07's Node guard test. The `docs/design/` fixture lives under `samples/`, and AC6's scaffold copies only `samples/brief.md` into the run directory's `.planning/seldon/`. Every scaffold copies fixture files from `samples/` and does nothing else. Evidence: `.planning/phases/1/CONTEXT.md` D-07; mother's ruling on AC6.
- D-13 (eval cases): The case proving "writes nothing until confirmed" allows Write and grades `tool_used` Write max 0, so a premature write is possible and caught. The new fast-path brief case's dump leaves at least one section unstated but inferable, so a tagged guess has to appear. Section completeness is graded through the check's result line, which Seldon repeats in its final message, and a regex on the brief file is also available. Evidence: `evals/fast-path/prompt.md` (allows only Skill and AskUserQuestion); `.planning/ROADMAP.md` phase 2 criteria 1 and 2.
- D-14 (phase 1 replay): Phase 1's replay case stays. When the user confirms coaching, Seldon still names the project before its first coaching question, so the `Brindlewick` grader keeps passing. Evidence: `evals/replay/prompt.md`; `evals/replay/graders/recalls-transcript-fact.md`.
- D-15 (eval mechanics): New replay histories are hand-written in phase 1's record shape (a `parentUuid` chain, `sessionId`, `cwd`, `version`, `type`, `message`), each ending on an assistant prose question, with UUID-shaped `sessionId`s so `evals/.gitignore` ignores the session file a run writes. Eval verification runs in the main tree, never from a worktree executor. The README's eval command gains `--scaffold`. Evidence: `evals/replay/history.jsonl`; `evals/.gitignore`; `.planning/phases/1/SUMMARY.md` deviations.
