## Durable decisions

- D-01 (hash stamps): `prd.md`, `spine.md` and `epics.md` each record a hash of their parent file (`brief.md`, `prd.md`, `spine.md`), and `lib/check.mjs` prints that hash, so the model never computes one. The brief carries no stamp. A link is stale when the parent's current hash differs from the recorded one, so a hand edit counts. The hash covers the parent's whole file, its own stamp line included, which is what carries a change down the chain. This replaces "revision" in the ruling phase 6 carried into this phase. Rejected: revision counters, which miss hand edits, and counters that bump only when an entry changes, which also let a PRD change that touches no spine decision reach no epic. Evidence: `.planning/phases/6/CONTEXT.md` line 10; `skills/seldon/SKILL.md` lines 660-663 ("the user may have edited the file by hand since. Build from the file as it stands."); owner's ruling.
- D-02 (when a stamp is written): Every write of `prd.md`, `spine.md` or `epics.md` records the parent's current hash, on create as well as on rerun, including a rerun over a stale link that changes nothing else. Rejected: stamping only on rerun, which leaves a document made after this phase reading fresh forever. Evidence: D-01; owner's ruling.
- D-03 (where a stamp sits): A stamp is its own line directly under the `# ` title, before the first `## `, the zone the spine and epics `Retired:` lines already use. Rejected: YAML frontmatter above the title, which failed all 23 sample docs' own check in the analyzer's probe, and a stamp at the end of the file, which became body text of the last section and broke `samples/epics.md`'s last `**Spine decisions:**` field. Evidence: `lib/check.mjs` lines 38-53 (every line before the first `## ` is ignored, and the first non-blank line must be `# `); `docs/FORMAT.md` (the `Retired:` lines); `evals/spine-rerun/graders/retires-dropped-id.md`; owner's ruling.
- D-04 (no stamp reads fresh): A document with no stamp reads as fresh. The per-file modes don't require a stamp, but hold one that's present to its exact form, the way `Kind:` is read. The first rerun writes the first stamp. Rejected: no stamp reading stale, which reroutes every existing design on its next bare `/seldon`, changes the route of 5 existing cases (`full-walk`, `spine-from-prd`, `spine-job`, `spine-outside-input`, `resume-later`) and, with stamps required, failed 72 of 82 check tests in the analyzer's probe. Evidence: `lib/check.mjs` lines 139-145; `evals/*/seed.sh` (28 cases seed unstamped Seldon docs); phase 6 D-02 (`/code/cadence/.planning/seldon/` holds `brief.md` and `prd.md`); owner's ruling.
- D-05 (where a bare `/seldon` goes): The earliest stale link wins and outranks a missing later document. A stale PRD goes to the PRD rerun; otherwise a stale spine goes to the spine rerun; otherwise stale epics go to the epics rerun; otherwise today's routes run. Each of the three has a fixed resume line said before the rerun, and the PRD line gets its own eval case. The later-release line comes only when all four documents exist and nothing is stale. A named step (`/seldon prd`, `/seldon spine`, `/seldon epics`) runs as today, with no stale check, because it's the user's explicit pick. Rejected: routing only on a stale spine or epics, which leaves phase 3 D-04's deferral unmet, and a named step first naming a stale upstream link. Evidence: `skills/seldon/SKILL.md` (section 2's route order); `.planning/ROADMAP.md` lines 86-87; `.planning/REQUIREMENTS.md` FLOW-03; phase 3 D-04; owner's ruling.
- D-06 (the conflict check): The conflict check sits at the three routes that change a `prd.md` that's already there: the `/seldon prd` rerun, "PRD questions answered", and "Names changes" at the PRD confirm question. It runs after the change is worked out and before the first Edit, and only when `spine.md` exists. Two lines that today forbid reading the spine gain it as an input used only to name conflicts, and nothing from the spine enters the PRD. Rejected: the check in the `/seldon prd` route only, which lets a change named at the confirm question edit the PRD with no report. Evidence: `skills/seldon/SKILL.md` lines 657-658 ("The one other file a PRD step reads") and 709-713 (the rerun reads "and nothing else"); `.planning/phases/6/CONTEXT.md` line 10; owner's ruling.
- D-07 (what counts as a conflict): A conflict is found by comparing what a spine decision states or quotes with the requirement text and quotes the change alters or drops, never by requirement ID, because spine decisions name no requirement IDs. In the fixture, S-03 and LOAN-03 share the quote `> a reminder when something's due`. Rejected: matching by requirement ID, which finds no conflict in the fixture. Evidence: `samples/spine.md` lines 13-18 (no CAT, LOAN or NFR ID anywhere in the file); `samples/prd.md` lines 15-16; `docs/FORMAT.md` (the spine's quote sources); owner's ruling.

## Decisions

- D-08 (parent by file name): A stamp names its parent by bare file name, never by path. The stale check reads the files of one design folder, so a design in `.planning/seldon/<name>/` is compared only within that folder. With more than one design, the which-design question picks the folder before any stamp is read. Evidence: `lib/check.mjs` lines 219-231 and 247-262; `skills/seldon/SKILL.md` (the which-design question); phase 6 D-02, D-05.
- D-09 (each step writes its own stamp): Each step writes only its own file's stamp. A brief rerun still never writes or edits `prd.md`, so the PRD goes stale only through the hash mismatch. Evidence: `skills/seldon/SKILL.md` lines 624-625 ("Never write or edit `.planning/seldon/prd.md` on a brief rerun"); phase 3 D-04; `evals/brief-rerun/graders/prd-not-edited.md`, `prd-not-written.md`.
- D-10 (architecture.md): `architecture.md` stays out of the stale chain: no stamp, and nothing reports it stale. It has no format and no check, and `/seldon architecture` replaces it whole from the current files. Evidence: `docs/FORMAT.md` (the on-request file); phase 4 D-05; owner's ruling.
- D-11 (the stale check mode): A new `lib/check.mjs` mode reads one design folder's stamps. It prints one line per stale link, exits 1 when there is any, and prints the hashes a step records. The full check and the four per-file modes keep their current reads. Evidence: `lib/check.mjs` lines 247-253 (the modes table); `docs/FORMAT.md` (each per-file mode reads one file; the full check wants all four); `tests/check.test.mjs`.
- D-12 (the check on a bare `/seldon`): A bare `/seldon`, and the "go on" answer that mirrors it, runs the stale check after the Glob that finds the files and after any which-design question, but before any resume line. `evals/full-walk/graders/names-spine-first.md` and `evals/spine-from-prd/graders/names-prd-first.md` allow only Glob, Skill or a Read before the resume line, and both widen to allow the check's Bash call. Evidence: `skills/seldon/SKILL.md` (section 2; the resume line comes before the next tool call); `evals/full-walk/graders/names-spine-first.md`.
- D-13 (criterion 2 in two replays): After an applied PRD change, a bare `/seldon` says the spine's stale line, reruns the spine and stops at the spine confirm question. After the `/clear` words, the next bare `/seldon` says the epics' stale line and reruns the epics. The epics rerun reads only `epics.md`, `prd.md` and `spine.md`, never Cadence's roadmap. Evidence: `.planning/ROADMAP.md` lines 68 and 87; `skills/seldon/SKILL.md` (the `/clear` words; what the epics rerun reads); `evals/epics-confirm/`, `evals/confirm-clear/`.
- D-14 (the conflict question's route): The conflict question ends on fixed words and gets its own section 1 route. A go-ahead applies exactly the change the report described: from the conversation for "Names changes", worked out again from the files for a rerun. It then writes the new stamp, runs the PRD check and ends on the PRD confirm question. A decline writes and edits nothing. Any other reply writes nothing and asks the fixed question again. Evidence: `skills/seldon/SKILL.md` ("Brief change answered" and the which-design route); phase 4 D-09; phase 6 D-04, D-05; `.planning/phases/6/CONTEXT.md` line 10.
- D-15 (decline lines): A decline ends on a fixed line. When the change came from the brief (the rerun and "PRD questions answered" routes), the line says the PRD stays behind the brief and names `/seldon brief` to take the change back out of it. The same report shows again on the next bare `/seldon`, because the two files still disagree. A declined "Names changes" change came from the conversation, so the PRD isn't behind the brief, and its line says only that nothing was changed, without naming `/seldon brief`. Evidence: D-05, D-14; owner's ruling.
- D-16 (stamped fixtures): Stale cases are seeded only from stamped files under `samples/`, because a scaffold line can only `mkdir -p` or `cp` from `samples/`. The existing fixtures are stamped to tell their own story, and no duplicate folders are added. The top-level `samples/brief.md`, `prd.md`, `spine.md` and `epics.md` are stamped to agree, so the 7 cases that seed them together keep their routes. The rerun fixtures read stale where they pair a newer parent with an older child: `prd-rerun`'s newer brief, `spine-rerun`'s newer brief and PRD, and `epics-rerun`'s newer spine. A unit test pins that every sample stamp matches its parent's hash. Evidence: `tests/scaffold.test.mjs` lines 18-29; `evals/prd-rerun/seed.sh`, `evals/spine-rerun/seed.sh`, `evals/epics-rerun/seed.sh`; `diff samples/brief.md samples/prd-rerun/brief.md` (the reminder quote dropped, a no-reminders refusal added); owner's ruling.
- D-17 (the format): `docs/FORMAT.md` documents the stamp line, the hash it holds and the stale rule, and tells a reader to skip the stamp line. Evidence: `docs/FORMAT.md`; a grep for `planning/seldon` in `/code/cadence` outside `.planning` found no reader yet.
- D-18 (permissions): No grant changes. SKILL.md's `allowed-tools` stays phase 2 D-02's five entries, and the new mode falls inside `Bash(node ${CLAUDE_PLUGIN_ROOT}/lib/check.mjs:*)` and the README's `Bash(node $PWD/lib/check.mjs:*)`. Evidence: `skills/seldon/SKILL.md` lines 5-10; `README.md` line 66; `tests/skill.test.mjs`; phase 6 D-14.
- D-19 (SKILL.md size): SKILL.md is 65,786 bytes before this phase. The plan's first task measures whether it still loads whole with phase 7's text, the way phase 5 plan 4 did from a kept session transcript. Phase 7's rules move to a reference file the skill Reads only if it doesn't. Evidence: `wc -c skills/seldon/SKILL.md`; `.planning/phases/5/SUMMARY.md` (deviation: loaded whole at 55,644 bytes); owner's ruling.

## Flagged assumptions

- The hash algorithm and length, the exact stamp wording, and the order of the stamp and `Retired:` lines under the title are the planner's call - Likely; if wrong: the graders pin wording that gets changed later.
- Whether a step runs the stale check again after writing its stamp, to confirm the link now reads fresh, is the planner's call - Likely; if wrong: a mis-copied hash leaves the link reading stale until the next rerun writes it again.
- A whitespace-only hand edit marks the child stale, and the rerun that follows changes only the stamp - Likely, an accepted cost of D-01; if wrong: users rerun a step that changes nothing but its stamp.
- An eval trace shows a Bash call in the same one-line JSON shape as the Read and Glob calls the two resume graders match today, so widening them is a pattern change - Likely, the planner checks it against a kept trace; if wrong: the widened graders need a different form.
- Where Claude Code's skill loader starts cutting a large SKILL.md isn't known, which is why D-19 measures it - Unclear; if wrong: the tail of the file, the epics rules and the architecture route, stops loading with no error.
- Cadence's reader for `.planning/seldon/`, built in a Cadence phase after 4.4.0, skips the stamp line as `docs/FORMAT.md` says - Unclear; if wrong: the reader misreads the line under the title, and the format or the reader changes before the handoff works.
- Whether phase 8's readiness check reports stale links is phase 8's call - Likely; if wrong: a design handed off with a stale link reaches Cadence unreported.
