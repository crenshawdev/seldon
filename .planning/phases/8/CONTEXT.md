## Durable decisions

- D-01 (a separate agent): The readiness check is a Seldon plugin agent in `agents/readiness.md`, started as `seldon:readiness`, with `tools: Read` and Write, Edit and Bash disallowed. Its checking rules live in the agent file, not in SKILL.md. Rejected: a built-in general-purpose agent, which can write, and a toolless agent handed the three files as text, which the host may refuse to start. Evidence: `/code/cadence/agents/cad-assumptions-analyzer.md:1-12`; `/code/cadence/cadence-core/bin/skill-preload-proof.mjs:15-19, 47-48`; `skills/seldon/SKILL.md` (74,471 of 90,000 bytes); Daneel's ruling.
- D-02 (the grant): SKILL.md's `allowed-tools` gains one entry for the agent tool, scoped to `seldon:readiness` if the host allows scoping. `tests/skill.test.mjs`'s grant list and the README's grant sentence change with it. If the entry cannot be scoped to that one agent, work stops after the probe and the result goes to Daneel before any grant change is committed. This is the first change to the pinned five entries; phase 7's D-18 held for that phase. Rejected: an unscoped entry taken without that stop, which lets the skill start any agent. Evidence: `skills/seldon/SKILL.md:5-10`; `tests/skill.test.mjs`; `/code/cadence/skills/cad-context/SKILL.md:13` (lists `Task`); `/code/cadence/skills/cad-phase/SKILL.md` (starts no agent, lists none); Daneel's ruling. [corrected by plan-1 deviation: no Agent entry gates an agent start in the eval (run 3 started seldon:readiness with none), so phase 8 changed no grant]
- D-05 (when it runs): The check runs on a bare `/seldon` when all four documents are there and nothing is stale. It replaces the later-release line at `skills/seldon/SKILL.md:412`. The epics confirm keeps its `/clear` words, so the check never runs in the conversation that wrote the epics. No copy of the later-release line stays in `skills/`, `README.md` or `evals/`, and the `resume-later` case changes with it. Rejected: running it in the epics confirm turn, and a route name of its own such as `/seldon ready`. Evidence: phase 5 D-17; `README.md:47, 90`; `evals/resume-later/`.
- D-07 (the findings): The findings are exactly CHECK-01's three kinds: a PRD requirement no epic names, an epic that crosses a boundary the spine didn't fix, and a decision left open. A decision left open is a choice between parts that an epic needs and no spine decision makes. A guess tagged `[ASSUMPTION]` is an answered question and isn't a finding. A retired ID isn't a requirement no epic names. Rejected: counting `[ASSUMPTION]` tags, which makes every fast-path design report findings and takes away the clean samples' no-finding baseline; and a fourth kind for an epic too small to ship, which has no pass/fail definition that `samples/epics.md`'s E-03 passes. Evidence: `.planning/REQUIREMENTS.md:42`; `samples/prd.md`, `samples/spine.md` (their `[ASSUMPTION]` tags); `samples/epics.md:27-35`; `.planning/ROADMAP.md` (phase 9 fails a run on any finding); Daneel's ruling.
- D-10 (fix): Fix reruns one step in the same turn: the earliest step any finding names. A crossed boundary or a decision left open names the spine, and a requirement no epic names names the epics. The finding lines go into that rerun as its change. That is this phase's one named exception to "never the earlier conversation", and it's the mechanism phase 7's go-ahead uses. One step per turn: after a spine rerun the epics are stale, and the next bare `/seldon` reruns them through phase 7's stale route before the check runs again. After a `/clear` the fix route is gone, and a bare `/seldon` runs the check and reports again. Rejected: a rerun with no finding carried, which only renews the stamp so the same finding returns; and a fix that only names the command. Evidence: phase 5 D-08 (an epics rerun can't add a boundary); `skills/seldon/SKILL.md:177-186`; Daneel's ruling.
- D-13 (the command on a new project): On a project not under Cadence the line is `/cad-new-project --brief .planning/seldon`, with the short command name and no trailing slash. A named design prints its own folder, `.planning/seldon/<name>`. Rejected: `--brief .planning/seldon/brief.md`, which works on Cadence 4.4.1 and hands off the brief alone; `/cadence:cad-new-project`; and handing off only the top-level design. Evidence: `.planning/PROJECT.md:64`; `/code/cadence/skills/cad-new-project/SKILL.md:4` (`--brief <file>` today); phase 6 (named designs); Daneel's ruling.
- D-14 (the command under Cadence): On a project under Cadence the line is `/cad-phase add --brief .planning/seldon`, and a named design prints `/cad-phase add --brief .planning/seldon/<name>`. Never `/cad-milestone`, which closes a milestone and adds no phase. FLOW-08's wording, "the `/cad-phase` or `/cad-milestone` command", is met by `/cad-phase`, so the requirement row is unchanged. - D-20 (a check that could not run): When `seldon:readiness` can't be started, because the start is denied or refused, or it returns something that isn't in D-08's fixed forms, Seldon says in one fixed line that the readiness check did not run, with the reason in a few words. Evidence: `.planning/PROJECT.md:98` ("a report, not a gate"); Daneel's ruling.

## Decisions

- D-03 (what the agent is given): The agent is given the paths of `prd.md`, `spine.md` and `epics.md` in the working folder and nothing else: not the brief, `architecture.md`, the project's code or Cadence's files. The skill doesn't read those three documents to run the check; it relays what the agent returns. Evidence: `.planning/REQUIREMENTS.md:42`; `.planning/ROADMAP.md:95`.
- D-04 (the probe): Phase 8 opens with a probe plan on Daneel's SECURITY terms, fail-closed: phase 7's terms unchanged, plus (a) one throwaway probe case, at most two solo runs, nothing from the case committed; (b) the eval's allowed tools gain one agent-tool entry, scoped to the one Seldon agent if the host allows scoping; (c) the audit after each run also lists every agent start in the trace, and any start other than the Seldon agent stops the run and goes to Daneel; (d) if the entry can't be scoped to one agent, stop after the probe and bring Daneel the result before any grant change is committed to SKILL.md; (e) any seed gets the usual vet. The probe's four answers go to Daneel before the grader design for AC2 is fixed. Evidence: Daneel's ruling; phase 7 plan 1 (the size probe).
- D-06 (stale links): The check doesn't report stale links. It only runs after the bare `/seldon` stale check has found none, so a stale design is rerun before it can be checked. Evidence: `skills/seldon/SKILL.md` ("Where a run starts"); phase 7 CONTEXT.md:56.
- D-08 (the report): The report has fixed forms: one line per finding naming its kind, its IDs and the step that fixes it, and one fixed line when there are none. With no findings Seldon asks nothing and goes straight to the handoff command. Evidence: `.planning/PROJECT.md:98`; `.planning/ROADMAP.md:94`.
- D-09 (the question): With findings, the report ends on one fixed plain-prose question, fix or hand off as it is. Its question mark is the last thing in the turn, and nothing follows it. Section 1 of SKILL.md gains a route for the answer, the way the conflict question has one. Evidence: `skills/seldon/SKILL.md` ("Conflict question answered"); phase 7 SUMMARY.md (the spine confirm question's split); Daneel's ruling.
- D-11 (hand off as it is): Hand off as it is writes and edits nothing and prints the handoff command. Evidence: `.planning/REQUIREMENTS.md:43`; `.planning/ROADMAP.md:96`.
- D-12 (which command): The command is chosen by whether `.planning/PROJECT.md` exists, found with Glob and never Read. Evidence: phase 6 D-01; `/code/cadence/cadence-core/workflows/new-project.md:36-37`.
- D-15 (already built): On every under-Cadence handoff, named designs included, the command is followed by one fixed sentence saying that if Cadence has already built this design, there is nothing to hand off. Seldon reads none of Cadence's files to decide it and writes no marker. Evidence: `evals/new-design-name/seed.sh` (a built Cadence project with the same design at the top level); Daneel's ruling.
- D-17 (no record of a handoff): The handoff ends the run and leaves no record. A later bare `/seldon` on the same documents runs the check and prints the command again. Evidence: Daneel's ruling (no marker file).
- D-18 (the eval cases): Each of the roadmap's four success criteria gets at least one new eval case, and every readiness case allows the agent tool beside Skill, Read, Glob and Grep. One more case withholds the agent tool from its allowed tools and is graded on the did-not-run line being there and the no-findings line being absent; it starts no agent. How AC2 is graded is decided after the probe. Evidence: `.planning/ROADMAP.md:93-97`; `evals/results/phase-7-traces/` (`permissionMode: "dontAsk"`, no agent start in any kept trace); Daneel's ruling. ## Acceptance criteria

- [ ] AC1: With a design seeded so that one PRD requirement is named by no epic and one epic crosses a boundary no spine decision fixes, a bare `/seldon` prints a report that names that requirement by its ID on an uncovered-requirement line and that epic by its ID on a crossed-boundary line, each line naming the step that fixes it. It makes no Write and no Edit, and the turn ends on the fixed fix-or-hand-off question with nothing after its question mark.
- [ ] AC2: In a readiness case's trace, the skill starts exactly one agent, `seldon:readiness`, hands it the paths of `prd.md`, `spine.md` and `epics.md` in the working folder and no other file path, and makes no Read of those three files itself. The agent's own reads are those three files and nothing else.
- [ ] AC3: A replay that answers the question with fix, after a report whose only finding is a crossed boundary, edits `spine.md`, makes no Write or Edit to `epics.md`, and ends on the spine confirm question. A replay that answers hand off makes no Write and no Edit to any file and ends on the handoff command.
- [ ] AC4: With the clean samples seeded and no `.planning/PROJECT.md`, a bare `/seldon` prints the fixed no-findings line, asks nothing, makes no Write or Edit, and ends on `/cad-new-project --brief .planning/seldon`. With a named design as the working folder, the printed path is `.planning/seldon/<name>`.
- [ ] AC5: In a case that withholds the agent tool from its allowed tools, a bare `/seldon` over the clean samples prints the fixed did-not-run line, doesn't print the no-findings line, asks nothing, and prints the handoff command with the fixed not-checked line.
