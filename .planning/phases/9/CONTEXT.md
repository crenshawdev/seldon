A unit test fails when two copies of the size grader, or of either readiness-passes half, differ by one byte. Trace-grader copies differ by each case's own PRD IDs and aren't held equal. Rejected: a shared `evals/graders/` folder, which the runner's documented case shape doesn't include, and symlinks, which would need a probe run. Evidence: `claude plugin eval --help` ("case.yaml or prompt.md + graders/*.md"); `evals/*/graders/`; Daneel's ruling.
- D-02 (graders grade what the model wrote): A full grader goes only on a case whose graded turn wrote what the grader grades. No grader grades a seeded file. Rejected: graders on seeded documents, which test the fixtures rather than Seldon; and the full graders on all 58 cases, which fail every step case and every findings case on correct behavior. Evidence: `evals/*/seed.sh`; `evals/readiness-findings/seed.sh`; Daneel's ruling.

- D-08 (proving the graders fail): A committed `tests/graders.test.mjs` runs each new or changed full grader's pattern against a hand-made bad input and a matching good one, and fails when any full grader's pattern uses a form outside D-09. Rejected: scratch checks that are never committed (phase 3 D-21). Evidence: `.planning/phases/8/SUMMARY.md` Deviations (plan 6, no-spine-write); `tests/scaffold.test.mjs`; Cadence 4.4.1 `references/test-policy.md`; Daneel's ruling.
- D-09 (regex forms): A full grader's pattern uses only these forms: literals, character classes, `[\s\S]`, alternation, greedy and lazy quantifiers, `^` and `$` under the `m` flag, lookahead, and the one lookbehind `^(?<![\s\S])`. Passing runs already prove that lookbehind in the runner. Avoided: backreferences (`\1`, `\k<name>`), named groups, `\p{...}` escapes, any other lookbehind, and every flag except `i` and `m`. That keeps the patterns to forms the runner's engine and Node read the same way. Which engine the runner uses is unverified. Evidence: `evals/epics-from-spine/graders/every-requirement-once.md`; `.planning/phases/6/SUMMARY.md` Deviations (the no-secret `^(?<![\s\S])` fix); Daneel's ruling.
- D-10 (where eval runs go): Under John's rule, eval runs go only where behavior or a replayed history changes. A SKILL.md change (D-13) gets a solo run of every case whose graded turn ends on the changed question. A history change (D-17) gets its capture and its run. A new or changed grader is proven by `tests/graders.test.mjs` and by matching it against its case's kept trace in `evals/results/phase-8-traces/full-run-3/`. A grader that reads a file is checked against the file rebuilt from that trace's Write and Edit inputs over the seeded fixture, as phase 8 did for fixes-boundary. Each new grader kind also gets one real run, not one per case: one of full-walk for the trace and size graders, and one of readiness-agent for both halves of readiness-passes, which also settles D-07's question. The anchored recommends-fast-path graders need no run, because `^...$` under `m` is already proven in the runner. At most three tries per case, and any miss goes to Daneel. The planner lists every run in one place, with the count. Rejected: a run of every case a grader lands on, and a full-suite run in phase 9 (D-04). Evidence: `.planning/phases/8/SUMMARY.md` Deviations (John: "yes its over kill it will get tested well before release", "do it sorry i missed what was going on until now"); Daneel's ruling.
